# Experimental YYOS read-only management

**Authenticated management, native streaming and optional key-only SSH passed short normal-cold-boot checks on this exact profile. Public native configuration remains blocked; do not bypass the gate.** The [24-byte-password reboot loop and verified recovery](https://github.com/dev-zetta/LSCamoflash/blob/main/docs/yyos-recovery.md), controlled 15-byte trial and [enabled normal-boot acceptance](https://github.com/dev-zetta/LSCamoflash/blob/main/docs/yyos-native-media.md#native-enabled-normal-boot-short-acceptance) are separate evidence. Recorded microphone sound and owner-reported Tuya app connectivity passed. The earlier crash cause is unproven; direct VLC live playback, detailed app/recording behavior, repeated boots and long-term stability remain unresolved.

Public native configuration remains blocked pending write-path safeguards for active-service password rotation, independent enable-flag verification and fresh live application identity. Current native runtime acceptance does not authorize bypassing that block. New UI/payload deployment remains separate; this management payload is not a recovery procedure.

This separate payload is for the observed LSC 3225722 / SZ F26312, firmware V14.1.5, AK3918AV130 and exact `/appfs/bin/yy_cam` SHA256 `d76d632f41453f53d9d117582fc47073934f5e6ec9a9b7a0ebb1dd3824f6cba7`. It requires `/mnt/sdcard/LSCamoflash-yyos` on the verified writable VFAT `/dev/mmcblk0p1`. Another unit or binary must pass its own investigation; do not bypass these fixed guards.

The payload provides an authenticated HTTP dashboard on port 8080, backed by a static ARMv5 BusyBox and one read-only status CGI. A separately provisioned, regular `httpd.conf` outside `www/` must contain exactly one supported hashed account. There is no default password. The stock camera, network and configuration remain under vendor control. The payload has no settings, PTZ, recording browser, shell endpoint, reboot, firmware update, overlays, media encoder or additional ONVIF/discovery daemon.

Start it manually with its static BusyBox and `start.sh`; use `stop.sh` to stop only the matching owned HTTP process. PID, executable, full arguments and process start time must match before a signal is sent. Existing state and unknown payload files are refused. A failed start retains state if its owned HTTP child cannot be confirmed stopped. `startup.log` contains only bounded fixed lifecycle messages. Keep site credentials and private evidence outside the served directory, and stop the owned service before replacing the payload.

The Streams view displays allowlisted native RTSP and ONVIF addresses with an explicit public-configuration block. The controlled trial and subsequent normal boot accepted short decoding and RTSP Digest/ONVIF WSSE controls. Recorded microphone sound was accepted before that boot; post-boot audio decoded with zero samples. The web account does not protect other camera services. No status request enables or changes a native service. HTTP Basic authentication does not encrypt traffic; this experimental interface is intended for a trusted LAN.

The source shares the project's lightweight Fullhan interface design but uses an isolated YYOS profile and payload inventory. Project code and BusyBox retain separate licenses supplied by the host builder. The accepted normal boot retained the stock PID across a 503-second window while HTTP, SSH and native listeners ran. Physical service stop/restart, detailed app/recording behavior, stable repeated cold boots, user GUI and long-term use remain unverified.
