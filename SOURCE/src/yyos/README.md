# Experimental YYOS read-only management

**Known reboot-loop block: do not enable native RTSP/ONVIF or bypass the production configuration gate.** Repeated reboots followed a separate approved native-media attempt. The [short recovery boot and exact two-flag edit](https://github.com/dev-zetta/LSCamoflash/blob/main/docs/yyos-recovery.md) passed private verification, with enablement observed off and a password-set indicator. The exact password/authentication and reboot cause remain unverified. Host cleanup archived the debug entry and restored known normal management startup on the card; one subsequent normal cold boot passed short owner/read-only checks. Long-term stability remains unverified.

The pre-activation HTTP, recovery boot and one subsequent normal cold boot are bounded evidence, not long-term acceptance. New UI/payload deployment remains separate; this management payload is not a recovery procedure.

This separate payload is for the observed LSC 3225722 / SZ F26312, firmware V14.1.5, AK3918AV130 and exact `/appfs/bin/yy_cam` SHA256 `d76d632f41453f53d9d117582fc47073934f5e6ec9a9b7a0ebb1dd3824f6cba7`. It requires `/mnt/sdcard/LSCamoflash-yyos` on the verified writable VFAT `/dev/mmcblk0p1`. Another unit or binary must pass its own investigation; do not bypass these fixed guards.

The payload provides an authenticated HTTP dashboard on port 8080, backed by a static ARMv5 BusyBox and one read-only status CGI. A separately provisioned, regular `httpd.conf` outside `www/` must contain exactly one supported hashed account. There is no default password. The stock camera, network and configuration remain under vendor control. The payload has no settings, PTZ, recording browser, shell endpoint, reboot, firmware update, overlays, media encoder or additional ONVIF/discovery daemon.

Start it manually with its static BusyBox and `start.sh`; use `stop.sh` to stop only the matching owned HTTP process. PID, executable, full arguments and process start time must match before a signal is sent. Existing state and unknown payload files are refused. A failed start retains state if its owned HTTP child cannot be confirmed stopped. `startup.log` contains only bounded fixed lifecycle messages. Keep site credentials and private evidence outside the served directory, and stop the owned service before replacing the payload.

The Streams view displays allowlisted candidate native RTSP and ONVIF addresses, with an explicit warning that native enablement is blocked after the observed reboot loop. Do not enable those services; their authentication, decoding, audio and SOAP behavior are unverified. The web account does not protect other camera services. No status request enables or changes a native service. HTTP Basic authentication does not encrypt traffic; this experimental interface is intended for a trusted LAN.

The source shares the project's lightweight Fullhan interface design but uses an isolated YYOS profile and payload inventory. Project code and BusyBox retain separate licenses supplied by the host builder. Automated fixtures establish guarded software behavior; earlier live HTTP responses and one resource sample preceded the failure. Physical stop/restart, normal-app/recording coexistence, stable repeated cold boots, user GUI and long-term use remain unverified.
